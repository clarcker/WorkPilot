## 一、背景与对照

WeKnora `rag_stream` 流水线：

```
LOAD_HISTORY → QUERY_UNDERSTAND → CHUNK_SEARCH_PARALLEL → CHUNK_RERANK → CHUNK_MERGE → FILTER_TOP_K → … → CHAT_COMPLETION_STREAM
```

WorkPilot **实现后**链路：

```
anonymize ∥ query_understand(intent+rewrite) → sync
  → 混合检索（向量候选扩展 ∥ jieba tsvector）→ RRF → 分块合并
  → decide_tool ⇄ execute_tool → generate
  → llm_client 出口统一脱敏（仅外部 API）
```

| WeKnora 阶段 | 实现状态 |
|---|---|
| QUERY_UNDERSTAND 一次调用 | ✅ `query_understand_node` |
| CHUNK_SEARCH_PARALLEL 向量∥关键词 | ✅ RRF，默认 w=0.7/0.3 |
| 候选扩展 → 阈值 → TopK + hnsw | ✅ candidate_k=clamp(top_k*20,50,200) |
| 文档级权限过滤 | ✅ 保留（本项目差异点） |
| CHUNK_RERANK | ⬜ R5 |
| CHUNK_MERGE | ✅ 相邻合并/短块补邻/预算 4000 |
| 脱敏收口到 LLM 出口 | ✅ R0 |

- 正则闲聊快速通道；JSON 失败降级关键词+原 query
- 图：`START → anonymize ∥ query_understand → sync → …`

### R2 · 向量检索结构 ✅

- SQL 子查询：内层 `ORDER BY distance LIMIT candidate_k`，外层 `score >= min_score`（已改为 SQL 过滤，非 Python）
- `SET LOCAL hnsw.ef_search` + `iterative_scan=strict_order`（不支持则降级）
- `retrieval_top_k` / `retrieval_min_score` 配置化

### R3 · 混合检索 + RRF ✅

- 迁移 `0005_content_tsv`：`doc_chunks.content_tsv tsvector` + GIN
- `services/fts.py`：jieba `lcut_for_search` / `to_tsquery('simple', 'a | b')`
- pipeline 入库写 tsv；`scripts/backfill_tsv.py` 回填存量
- RRF：k=60，w_vec=0.7，w_kw=0.3；`rrf_score` 排序，`score` 展示
- 关键词侧异常降级纯向量
- 冒烟：`scripts/smoke_hybrid.py`（关键词查询 kw 命中 >0）

### R4 · 分块合并 ✅

- 去重 → 同文档相邻合并 → 短块(<200字)补前后邻 → 预算 4000 截断
- 引用仍指向原命中 chunk

### R5 · 重排 ⬜

未做；需 R3 评测数据证明收益后再上 sidecar。

## 附录：eval 基线（2026-09-18）

### 环境
- 语料：`backend/seed_docs` 24 份（含干扰/同名/无关/编号）
- 配置：`top_k=5` · `min_score=0.25` · 混合 RRF · **must_include/pinned 默认关闭** · merge=true
- 参数：`skip_generation=true` · `tool_dry_run=true`（**未评估答案正文**）

### E4 对照 + E5 最终结论（2026-09-18/20）

**A. 仅 retrieve（确定性，38 doc case + 早期 15 case 子集）**

| 配置 | doc_hit@3 | mrr |
|---|---|---|
| 纯向量 | 0.400 | 0.377 |
| 混合 RRF | **0.800** | **0.604** |
| 混合+kw配额（pinned 修复后） | 0.800 | 0.604 |

→ **R3 有效**（+0.23 mrr）；配额在检索层无增益。

**B. 配额 on/off × 3（`scripts/run_quota_ab.py`）**

| 配置 | mrr×3 | mean | delta |
|---|---|---|---|
| quota ON | 0.6044 ×3 | 0.6044 | — |
| quota OFF | 0.6044 ×3 | 0.6044 | **0.0** |

组内 ranks 完全相同。bug：merge 按 `must_include` 二次排序会吞掉配额换入项 → 已改为 **`pinned`**；修复后 A/B 仍 delta=0（本语料 RRF 已使 top_k≥2 条 kw，配额很少触发）。

**全链路单次**（含 LLM rewrite）：关 0.585 / 开 0.648，差 0.063，但含模型抖动，**不足以推翻检索层 3 次 A/B**。

**E5 决策：`retrieval_must_include=false`（默认关）。** 需要时用配置开启做实验。

## 附录：R2 EXPLAIN ANALYZE（2026-09-18）

规模：~270 embeddings / 24 份 ready 文档。

| 计划节点 | 说明 |
|---|---|
| Index Scan `idx_documents_visibility` | 先筛可见 documents |
| Index Scan `idx_embeddings_doc_id` | 再按 doc_id 取向量 |
| Sort top-N | 余弦距离，候选 Rows=21 |
| Execution Time | **2.27 ms** |

**结论：** 当前百级向量下规划器**未走 HNSW**，visibility+doc_id 嵌套循环更快；`hnsw.*` 设置在此规模无收益。

**是否冗余 visibility 到 embeddings：暂不采纳。** 待 chunk 到 1 万+ 或权限过滤拖慢查询时再测；若 HNSW+WHERE 成瓶颈再冗余或调 iterative_scan。
