## 数据库设计决策记录

**章节状态：** 已确认
**创建日期：** 2026-06-01

### 决策一：Embedding 向量维度 — 768

- 使用 `nomic-embed-text`（Ollama 本地部署）
- 无 GPU 环境下 CPU 可正常运行，768 维是该模型原生输出维度
- pgvector 中声明为 `vector(768)`
- 切换模型时必须重新向量化所有文档（见架构约束二）

---

### 决策二：文档权限模型 — 四级枚举 + 白名单关联表

```
doc_visibility ENUM:
  'global'          全体共享（所有登录用户）
  'non_customer'    非客服共享（除客服部门外）
  'dept_only'       本部门共享
  'specific_users'  本部门指定人员
```

- 仅 `visibility = 'specific_users'` 时使用 `doc_permissions` 关联表记录白名单用户
- 不引入黑名单机制，避免优先级冲突
- 超级管理员绕过所有权限限制

---

### 决策三：员工编号格式 — `{DEPT_CODE}{3位数字}`

- 示例：`HR001`、`RD023`、`CS007`
- `dept_code` 为大写英文简称（由超级管理员在创建部门时设置，如 `HR`、`RD`、`CS`）
- 创建账号时系统自动推荐（取该部门当前最大序号 +1），管理员可手动调整
- 员工编号与用户名（拼音）均唯一且不可修改，作为双重审计标识

---

### 决策四：向量索引类型 — HNSW

```sql
CREATE INDEX idx_embeddings_vector
    ON embeddings USING hnsw (embedding vector_cosine_ops);
```

- HNSW（分层可导航小世界图）：增量写入友好，插入即可检索，无需预训练
- IVFFlat 需提前聚类，冷启动数据量不足时效果差，不适合当前规模
- 当前文档规模（百份级）内存压力可接受
- 相似度计算使用余弦距离（`vector_cosine_ops`），适合文本语义匹配

### 表结构速览

| 表名 | 用途 |
|---|---|
| `departments` | 部门（dept_code + dept_name） |
| `users` | 用户（含三级角色枚举、employee_no） |
| `revoked_tokens` | JWT 黑名单（强制登出） |
| `documents` | 文档元信息（含四级权限枚举） |
| `doc_permissions` | 文档指定人员白名单（many-to-many） |
| `doc_chunks` | 文档分块（含页码、标题） |
| `embeddings` | 向量（vector(768)，HNSW 索引） |
| `conversations` | 对话会话（含归档状态） |
| `messages` | 单条消息（含 sources JSONB） |
| `audit_logs` | 审计日志（不可删除，无外键） |
| `system_config` | 系统配置 KV 表 |
