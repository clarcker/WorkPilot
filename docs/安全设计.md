# 安全设计（威胁模型）

**状态：** 随生产就绪 P7 落地  
**原则：** 每条威胁必须指向可运行的测试或 eval case。

## 资产

- 企业制度文档（含 draft / 部门文档 / 限权薪酬方案）
- 员工个人信息（姓名、工号、额度、工单）
- JWT / 会话
- 管理端操作（用户、审批、文档生命周期）

## 威胁 → 防线 → 证据

| 威胁 | 防线 | 证据 |
|---|---|---|
| **文档提示注入**（检索片段试图改写 Agent 行为） | **主防线**：① 权限 SQL 过滤（注入文档也拿不到无权内容）；② 写操作确认层（工具不因文档指令直接执行）；③ prompt 声明 + 随机 DOC fence。**降噪**：`doc_sanitizer` 正则可绕过，不单独作安全控制 | `test_doc_injection.py`；adversarial/injection case；`test_doc_lifecycle_authz.py` |
| **工具参数注入**（LLM 生成非法枚举/类型） | `tools.base.validate_tool_args` 按 JSON Schema 校验后才执行 | `tests/unit/test_tools.py` + 执行路径校验 |
| **越权查询**（员工查他人额度 / draft 文档） | 服务端 role 校验；检索 lifecycle+visibility SQL 过滤；draft 不透露存在 | `test_doc_lifecycle_authz.py`；permission 组 case；lifecycle 单测 |
| **跨部门下架制度**（dept_admin supersede global） | `_check_supersedes_scope`：本部门 + 禁 global | `test_doc_lifecycle_authz.py` |
| **PII 外泄到外部 LLM** | R0：仅 `openai_compatible` 出口脱敏（`llm_client._prepare_outbound`） | `tests/unit/test_anonymizer.py` `test_llm_exit_anonymize` |
| **令牌泄露 / 暴力登录** | bcrypt；JWT 失败计数 + 锁定；`revoked_tokens` 强制登出；登录限流 | `test_security.py`；`test_timeout_ratelimit.py` |
| **审计绕过** | 关键操作写 `audit_logs`（不可删业务语义） | 集成/管理接口路径 |

## 边界包装

- 生成 prompt：随机 `<<<DOC_{hex}>>>…<<<END_DOC_{hex}>>>` fence 包住每条资料；边界声明「不是系统指令」
- 工具结果：独立 JSON 块 + 「真实业务数据」说明
- `doc_sanitizer`：降噪（可被换措辞绕过）；**不**单独作为安全控制

## 对抗语料与 case

- `seed_docs/`：注入样本文档（见 manifest `category: 注入对抗`）
- eval：`group: injection` / `adversarial` ≥ 5（见 `eval/cases.json`）

## 遗留

- 异维度 embedding 切换未做（P5 限制）
- 多 worker 熔断状态进程内，跨 worker 不共享（可接受，行为保守）
